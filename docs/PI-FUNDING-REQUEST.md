## Goal

CoreGuard wants to bring the execution-truth layer to Pi Network:
deterministic, replayable proof of what was authorised versus what executed,
fail-closed, before the transaction settles — the same pattern already proven
on Core DAO and Stellar.

This document is a funding request template for that work. It is bilingual
(English · العربية) and claim-disciplined: no revenue, customers, partners,
funding or audits are claimed until a named event with evidence exists.

## What is being requested

1. **Pi Browser verification overlay** — a prototype overlay that runs a Pi
   DApp transaction through CoreGuard and shows the user a one-line receipt
   summary before sign-off. UNKNOWN stays HELD.
2. **Pi Wallet pre-sign check** — a pre-sign verification step: ALLOW / DENY
   / HOLD with a verifiable receipt, so a wallet never signs a transaction it
   cannot explain to the user.
3. **Pi DApp SDK** — reuse of `@coreguard/sdk` from Core and Stellar, with a
   Pi Network adapter stub ready for the mainnet launch.
4. **Pi mainnet commitment anchor (prepared)** — a stub registry contract and
   a proof template ready for the Pi mainnet launch.
5. **Pi ecosystem attestation service** — Pi ecosystem services issue execution
   attestations for the transactions they process, giving users and auditors a
   verifiable record.
6. **Cross-network anchor with Core + Stellar** — the same verifier and receipt
   format run on all three networks, so a multi-chain wallet, agent or auditor
   gets one proof format across Core, Stellar and Pi.

## Why Pi Network needs this now

Pi Network is moving toward mainnet and an open developer ecosystem. The Pi
Ecosystem Summit (Nov 17–19, 2026) and the Pi Next hackathon (with a $200,000
USDT prize pool) are visible on the Pi Network side. That is exactly the moment
an execution-truth layer becomes useful: once value can move on Pi, every
transaction needs a proof a user, an auditor or a regulator can re-derive.

## Milestone-gated funding arc

The funding arc is milestone-gated, in the style of the Stellar Community Fund
model:

1. **Gate 0 — preparation (now → summit).** Materials ready: one-pager,
   pitch structure, hackathon participation plan, ecosystem partner outreach
   plan, funding request template. No claim of funding yet.
2. **Gate 1 — summit showcase (Nov 17–19, 2026).** CoreGuard presented as the
   execution-truth layer for Pi Network. Hackathon participation (Pi Next).
   Ecosystem partner outreach. No signed partnerships claimed yet.
3. **Gate 2 — pilot (post-summit, post-mainnet).** Once Pi mainnet is live,
   the anchor is deployed, pilots ship with Pi wallets, DApps or services.
   Reviewed and verified by Pi Network reviewers.
4. **Gate 3 — adoption scale.** Pi ecosystem services ship an attestation
   service, demonstrated adoption across a growing set of Pi DApps, wallets
   and services.

Each gate is reviewed and verified before the next. No claim of funding beyond
the gate that has evidence.
